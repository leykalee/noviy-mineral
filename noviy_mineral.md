# Задача

Разработай с нуля современный адаптивный интернет-магазин **«Новый Минерал»** на основе брифа заказчика и анализа сайтов-конкурентов.

Сайт продаёт:

* коллекционные минералы;
* изделия из натурального камня;
* украшения;
* книги;
* сопутствующие товары.

Каталог большой — **более 2000 товаров**, поэтому сайт должен проектироваться как полноценный масштабируемый интернет-магазин, а не как небольшой лендинг с каталогом.

Ценовой сегмент: **эконом + средний**.

Главная задача сайта:

> дать пользователю быстро найти конкретный минерал или подходящий красивый товар, изучить именно тот экземпляр, который продаётся, добавить его в корзину и оформить заказ.

---

# 1. Перед началом работы

Сначала изучи эти источники.

## Страница заказчика

https://vk.ru/noviy_mineral

Используй страницу для понимания существующего бренда, визуального языка, ассортимента и коммуникации.

### Логотип

На сайте должен использоваться **реальный логотип «Новый Минерал» со страницы VK**.

Не создавай новый логотип.

Если технически возможно получить логотип со страницы:

1. найди максимально качественную версию;
2. сохрани в `/public/brand/`;
3. используй на сайте.

Не вставляй скриншот всей аватарки, если внутри неё можно аккуратно выделить сам логотип.

Если автоматически получить файл не получается:

* не придумывай логотип;
* создай временный аккуратный текстовый fallback «Новый Минерал»;
* вынеси источник логотипа в отдельный компонент/config;
* отметь в README, какой файл необходимо заменить.

# 3. Что взять у конкурентов

## Kamnevedy

Полезно:

* большой каталог;
* отдельная навигация по минералам;
* возможность искать товары по происхождению;
* месторождения;
* широкий ассортимент;
* категории;
* новые поступления;
* акции;
* справочная информация.

Главный вывод:

> каталог должен иметь несколько способов входа, а не только стандартное дерево товарных категорий.

Пользователь может знать, что ему нужен:

* флюорит;
* минерал с Урала;
* подарок;
* камень до 3000 ₽;
* изделие из малахита;
* украшение;
* конкретный тип экземпляра.

Все эти сценарии должны поддерживаться.

---

## Rusmineral

Полезно:

* конкретный экземпляр имеет собственный артикул;
* цена относится именно к этому экземпляру;
* товары могут иметь состояние «зарезервирован»;
* в каталоге важны фильтры и сортировка;
* можно быстро перейти от списка к покупке конкретного образца.

Возьми эту предметную модель, но сделай интерфейс значительно современнее.

---

## Leonmin

Полезно:

* глубокая предметная классификация;
* отдельные коллекционные минералы;
* агаты;
* полированные камни;
* изделия;
* окаменелости;
* аксессуары;
* товары для коллекционеров;
* указание месторождения;
* размеры конкретного экземпляра.

Особенно важно сохранить идею:

> пользователь покупает не абстрактный «аметист», а конкретный физический экземпляр аметиста с фотографий.

# 4. Что НЕ копировать у конкурентов

Не повторять:

* старомодную визуальную стилистику;
* плотные текстовые меню;
* мелкую типографику;
* перегруженные страницы;
* интерфейсы начала 2010-х;
* плохую мобильную адаптацию;
* визуальную иерархию старых интернет-магазинов.

Используй их как источник бизнес-логики, а не визуального решения.

---

# 5. Визуальное направление

Из брифа:

* фирменный цвет — **бирюзовый**;
* заказчик хочет **яркие краски**;
* одновременно хочет **свой узнаваемый стиль**;
* не выбран строгий минимализм;
* не выбран тёмный premium.

Нужно сделать современный, чистый, выразительный сайт, где цвет дают прежде всего **сами минералы**.

## Концепция

Основа:

* светлый фон;
* очень качественные крупные фотографии минералов;
* нейтральная типографика;
* бирюзовый как основной брендовый акцент;
* дополнительные природные цвета можно брать из фотографий камней;
* много воздуха;
* достаточно крупный UI;
* минимум декоративного шума.

Сайт должен выглядеть современнее всех трёх референсов.

---

# 6. Не превращать сайт в generic e-commerce

Избегай визуального шаблона:

* белая карточка;
* огромный border-radius;
* маленькая картинка;
* badge;
* кнопка;
* ещё десять одинаковых карточек;
* случайный gradient.

Не делай сайт похожим на:

* SaaS;
* маркетплейс электроники;
* шаблон Shopify;
* шаблон интернет-магазина из UI kit.

Предмет сайта — необычный и визуально сильный.

Используй это.

Минерал должен выглядеть как **предмет коллекции**, а не как SKU шампуня.

---

# 7. Целевая аудитория

Учти минимум два сценария.

## Новичок

Может вообще не знать названий минералов.

Ищет:

* красивый предмет;
* подарок;
* что-нибудь необычное;
* определённый цвет;
* товар в рамках бюджета;
* украшение интерьера.

Ему нужны:

* визуальные категории;
* подборки;
* понятные человеческие названия;
* фотографии;
* простой поиск.

---

## Коллекционер

Знает, что ищет.

Например:

* «флюорит Дальнегорск»;
* определённое месторождение;
* конкретный минерал;
* размер;
* происхождение;
* редкий экземпляр.

Ему нужны:

* хороший поиск;
* глубокие фильтры;
* характеристики;
* артикул;
* месторождение;
* размеры;
* вес;
* качественные фотографии.

Сайт должен удовлетворять обе аудитории.

# 30. Поиск

Поиск должен быть хорошо видим в Header.

При focus / вводе открыть intelligent search panel.

Например запрос:

`флю`

показывает:

### Минералы

Флюорит

### Товары

фотографии 4–6 товаров

### Возможно

месторождения или категории.

Поиск должен понимать:

* название;
* артикул;
* минерал;
* месторождение;
* регион;
* категорию.

Enter:

```text
/search?q=флюорит
```

* уже применён.

После применения стоимость должна реально пересчитываться.

Не делать декоративную форму.

# 36. Checkout

Checkout должен быть быстрым.

Не заставлять пользователя проходить пять отдельных экранов.

Использовать одну страницу.

Поля:

## Контакты

* Имя
* Телефон
* Email

## Доставка

* Город
* Способ доставки
* Пункт выдачи / адрес

## Оплата

* доступные способы

## Комментарий

необязательный.

# 37. СДЭК

Из брифа:

* автоматический расчёт доставки;
* автоматическое создание накладной;
* отмечен **СДЭК PAY**.

Раздели в коде две ответственности:

```text
DeliveryProvider
PaymentProvider
```

Не смешивай их в одном компоненте.

Если credentials отсутствуют:

создай mock implementation.

Не имитируй настоящую оплату пользователю.

---

# 38. Delivery

Архитектура:

```ts
interface DeliveryProvider {
  calculate(...)
  getPickupPoints(...)
  createShipment(...)
}
```

Checkout должен быть готов показать:

* ПВЗ;
* курьерскую доставку;
* стоимость;
* срок.

Если реальный API не подключён, demo provider должен возвращать тестовые данные.

---

# 39. Payment

Архитектура:

```ts
interface PaymentProvider {
  createPayment(...)
  getPaymentStatus(...)
}
```

Подготовить интеграционный слой под CDEK Pay.

Credentials только через environment variables.

Никаких ключей в frontend.

# 40. Уведомления

По брифу обязательны **уведомления на email**.

Реализовать abstraction:

```ts
interface EmailProvider {
  sendOrderCreated(...)
  sendPaymentConfirmed(...)
  sendOrderShipped(...)
}
```

Если production provider не задан — использовать dev/mock provider.

Telegram-бот НЕ является обязательным требованием текущего брифа.

МойСклад/1С также НЕ считать обязательными для MVP.

Архитектуру можно сделать расширяемой, но не тратить на них основное время.

# Главный принцип

Не создавай сайт «о минералах».

Создай **удобный современный интернет-магазин конкретных коллекционных экземпляров и изделий из натурального камня**.

Визуальная ценность — сами минералы.

UX-ценность — возможность быстро найти подходящий экземпляр среди каталога более 2000 товаров.

Коммерческая ценность — короткий и понятный путь:

**нашёл → изучил → доверился → добавил → оформил заказ.**
